# ConstraintOps

ConstraintOps turns broken, messy, low-resource situations into clear operating
plans.

This project is not starting as SaaS. It starts as a productized service that
can be delivered manually with free tools, local files, public research, and
careful review.

## Core Thesis

Most systems are designed for people with money, stable hardware, clean records,
identity documents, paid APIs, and room to fail.

ConstraintOps is for the other operating mode: incomplete data, hostile tools,
missing context, damaged systems, no budget, and no clean reset button.

## First Service Line

AI Damage Triage

When an AI assistant, automation, shell command, search feature, or bad workflow
causes harm, ConstraintOps reconstructs what happened and turns it into a
prevention plan.

## Other Service Lines

- Mess-to-Map Report
- Survival Stack Audit
- Research-to-Opportunity Brief
- Codebase Sprawl Triage

Each service starts as a manually delivered report. Software comes later only
after the workflow proves repeatable.

## Working Rule

Sell clarity before selling software.
